# Android privacy facts — Bobby 1.2.0 (10)

Source audit: 2026-10-11, `android/play-rc`. This is a code inventory for the public privacy policy, not evidence of a real-phone session. The release configuration is FCM off and an empty Google RevenueCat key. References are repository-relative file and line; no upload signing material was inspected.

## Microphone and voices

- A person **holds the input control below the sphere to dictate and releases to finish**; a short tap opens typing. The microphone is not always listening. The page starts/stops native dictation on that gesture (`android/nucleo/src/app/60-fsm.js:247`, `:357`, `:389`; onboarding `android/nucleo/src/onboarding/60-fsm.js:258`). Native permits it only in the foreground, after the risk notice and with no sheet open (`android/app/src/main/java/xyz/bobbyprotocol/android/MainActivity.kt:276`).
- Only Android's explicit **on-device** recognizer is used, on Android 12/API 31 or later when available. There is no network-recognizer fallback; typing remains available. The microphone permission is checked first, speech buffers are ignored, and partial/final text goes to the local page (`android/app/src/main/java/xyz/bobbyprotocol/android/platform/AndroidVoice.kt:54`, `:77`, `:85`, `:107`, `:114`). Bobby sends **no microphone audio** to its server, OpenAI or an external transcription service.
- A hold is cancelled at **60 seconds**; release waits up to **1.5 seconds** for final text. Leaving the foreground cancels recognition, destroys the recognizer and stops playback (`AndroidVoice.kt:125`, `:149`, `:329`; `MainActivity.kt:460`). Text selected as the question is sent as described below. No raw dictation/audio recording is persisted by Bobby.
- Reading a reply aloud is different from recording speech: the app sends up to 800 characters of narration, selected voice and language/locale to `/api/bobby-voice-free`, which returns synthesized audio (`android/app/src/main/java/xyz/bobbyprotocol/android/data/BobbyRepository.kt:309`). Audio temporarily lives in private `cacheDir` as `bobby-voice-*.mp3`; playback completion/stop removes it (`AndroidVoice.kt:180`, `:326`). Companion selection previews use bundled clips, or a system TTS voice explicitly chosen to require no network (`AndroidVoice.kt:198`, `:221`). Briefing audio also uses private temporary cache (`android/app/src/main/java/xyz/bobbyprotocol/android/platform/BriefingNarrator.kt`).

## What requests send

All app transport uses HTTPS, prohibits cross-host redirects, and keeps auth native. Ordinary Bobby requests include an installation UUID (`x-bobby-device`), `x-bobby-platform: android`, Origin and, when signed in, an account bearer. Locale fields are language/locale/country selected from interface/system region, **not GPS**. Only opted-in signed-in reads carry `x-bobby-memory-opt-in: 1` (`data/BobbyRepository.kt:46`, `:93`, `:587`). HTTP inherently discloses an IP address to the receiving infrastructure; the anonymous price exception below is not IP anonymity.

The AI and voice processing are server mediated. The public policy must name the server's actual processors/retention; this Android inventory alone cannot establish those facts.

**Server analytics are separate from an SDK:** normal Android access/read calls can record first-party device/account access and read outcome events in the server funnel (`api/_lib/access.ts:105`, `:125`). When configured, the server can forward a salted installation hash, account UUID, event/platform/surface/outcome detail to Amplitude (`api/_lib/amplitude.ts:25`, `:47`). No Android analytics SDK is needed for this collection; confirm whether that server integration is enabled and its processor terms/retention. These paths collect country/region only for `platform === 'web'`, not Android (`access.ts:112`, `:128`; `api/_lib/geo.ts:18`). They use a network hash for security; hosting infrastructure still receives the IP. Do not describe Android as having no service analytics.

## Notifications

All notifications in this release are **posted locally**. Thesis reminders and follow-ups use one-time WorkManager work (`platform/AndroidLocalNotifier.kt:49`); briefing-ready notices use an opted-in periodic background inbox check and may perform authenticated API calls (`platform/BriefingReminders.kt:43`, `:67`). Do not describe all background reminders as offline or claim the app never checks in the background. No exact alarm access. Android may delay work, especially while idle.

Thesis reminders contain no asset name. Follow-ups can include an asset and have a Stop action; a public version omits the asset only when the phone hides sensitive lock-screen content. An ordinary Android lock screen can show the asset (`platform/AndroidLocalNotifier.kt:71`; `v18/harness/HarnessCenter.kt:921`). Work checks current reader/risk consent; changing accounts cancels outgoing work. FCM is not in this release.

## Deletion and sign-out

- In-app Delete account waits for confirmed server success, removes native memory opt-in and session/OAuth credentials, advances the account epoch, then broadcasts local deletion (`data/BobbyRepository.kt:412`). The UI removes the account's Núcleo profile/read ledger, equipment and briefing preferences (`ui/BobbySheet.kt`, delete-account branch; `nucleo/NucleoSession.kt:295`; `equipment/EquipmentStore.kt:44`; `platform/BriefingReminders.kt:39`).
- V18 deletion removes that account's authored theses, nudge history, memory consent/offer state, invitation account state, follow-up ledger/plan and notices; the purchase journal is retired (`v18/V18Runtime.kt:392`; `v18/memory/MemoryNudges.kt:73`; `v18/invite/InviteNudges.kt:100`; `v18/harness/HarnessCenter.kt:670`; `billing/BillingStore.kt:31`). Device settings/installation id/permission history and a device-owned pending invitation are not deleted. Clearing app storage removes these too.
- Server implementation deletes Bobby identity and cascading account data, then Supabase Auth user; de-links agent trade rows. Public blockchain records and limited security/audit records may remain. This is code evidence, **not a live deletion test**, and Android creates no blockchain transactions (`api/account.ts:139`, `:164`, `:180`).
- **Sign-out is not deletion**: session and OAuth attempt are removed, quota reset, requests/voice fenced by the changed epoch (`data/BobbyRepository.kt:386`; `platform/AndroidVoice.kt:83`). Account-scoped local profile/theses/follow-up history remain isolated on the phone for that account; a later sign-in can restore them. Outgoing notifications are cancelled. Device preferences, installation id and guest data remain.
- Deletion from another device/revoked session can only sign this phone out; it cannot distinguish why. The account's local theses/follow-up notes stay inaccessible until that account returns or app storage is cleared (`android/README.md:40`). Never promise remote erasure of every installed phone.

## Release libraries and network behavior

- **RevenueCat Purchases 10.15.1 / transitive Google Play Billing** are dependencies, but the empty `goog_` key means the coordinator returns before SDK configuration, login, offerings, purchase or restore. No RevenueCat customer/receipt request is made by this release configuration (`android/app/build.gradle.kts`, dependencies; `billing/RevenueCatClient.kt:47`; `billing/BillingCoordinator.kt:68`, `:91`; `BillingCoordinatorTest.releaseWithoutGoogleBillingNeverInitializesPurchasesOrLaunchesAStore`). Server access checks still occur independently. Do not infer that RevenueCat processes no account data anywhere in Bobby's wider service.
- **Firebase Messaging** is conditional on `BOBBY_FCM_ENABLED=true` and excluded from the FCM-off release; `DisabledPushRuntime` has no registration or provider traffic (`android/app/build.gradle.kts`, conditional dependency/source set; `android/app/src/noFcm/java/xyz/bobbyprotocol/android/push/PushRuntimeFactory.kt:3`). FCM-on compatibility CI is a different configuration, not the supplied bundle.
- **OkHttp 4.12.0** carries the requests above. **AndroidX WebKit** serves bundled assets in an isolated WebView and bridges allow-listed messages; no account bearer is exposed to JS (`platform/NucleoWebView.kt`; `data/BobbyRepository.kt:41`). **AndroidX Browser** opens sign-in/public support pages in the system browser.
- **AndroidX EmojiCompat** is a transitive UI dependency. Its optional downloadable-font startup initializer is removed in `android/app/src/main/AndroidManifest.xml:25`; Bobby uses system emoji fonts and does not initiate that Google font-provider fetch. WorkManager startup is retained. The merged release manifest is checked in `android/tools/check-release-bundle.py:28`. Older system fonts may lack newer emoji glyphs.
- **AndroidX WorkManager**, Compose, activity/fragment/core/lifecycle and Kotlin coroutines support local rendering/scheduling. They are not analytics or advertising SDKs in this code. WorkManager persists local work inputs. System speech/TTS remain governed by the selected on-device services.
- No Firebase Analytics, Crashlytics, AdMob, advertising id, location SDK, contact access or camera/media collection is configured by the Android sources/dependencies. Bundle inspection is a separate CI gate; this file does not pretend a dependency manifest proves every runtime behavior.
