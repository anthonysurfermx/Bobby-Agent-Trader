## Criterios para cerrar la revisión

1. Preservar el manifiesto de fuente del build aprobado y los recibos históricos. Cada nueva mejora debe regenerar release y producir recibos vinculados a su fuente, herramientas, exit codes y hashes.
2. Revisar los 59 warnings de lint y completar matriz FCM; **ejecutar** instrumentación por separado. JVM ya PASS no equivale a aceptación runtime de callbacks de audio, fences de cuenta/consentimiento u OAuth. Conservar pruebas que fallen ante la regresión.
3. Aceptar físicamente Núcleo/onboarding, seis idiomas, riesgo v6, perfil, dictado, audio/mute/cancelación, ayuda Isla y PNG compartido. Registrar APK exacto, dispositivo/API/page size y resultado por flujo sin datos privados.
4. Verificar por separado auth/backend, reportes, persistencia/sincronización, compras/restore, push y telemetría. Cerrar una pantalla o simular una respuesta no cierra estos contratos reales.
5. Conservar el PASS estático final vinculado a estos artefactos; si cambia la fuente/release, repetir firma, paquete, icono morado, assets, alineación nativa y AAB/manifest. Instalación física o futuro borrador Play requieren sus evidencias y autorización correspondientes.

La revisión debe entregar una matriz **verificado / no verificado / bloqueo / siguiente comprobación**, con versión y alcance por cada prueba. No hay una afirmación de “100 % funcional” basada en este handoff.
