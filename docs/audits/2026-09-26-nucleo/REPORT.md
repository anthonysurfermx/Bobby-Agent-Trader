# Núcleo audit — 26 September 2026

Baseline: `ios/nucleo-preview` at `3f34a91` (iOS 1.5, build 40). Audit work: local `codex/nucleo-audit` branch. The changes in this report are **not** in the uploaded build 40 or the live web deployment. No production deployment, database write, phone installation, TestFlight upload, App Store submission, merge, or push was made by this audit.

## Resumen para Anthony

Núcleo conserva lo que aprobaste: esfera de vidrio Deep core, debate de tres agentes, avatares fuera del vidrio, recompensa al guardar y cuenta después de recibir valor. Las seis capturas del build 40 muestran esa experiencia; tienen el tamaño aceptado por Apple y no incluyen transparencia. La voz transcribe en el dispositivo, el aviso de riesgo se exige antes de enviar una pregunta y la salida a la app clásica está limitada a Debug. Hice una lectura real en inglés y otra en español en el simulador: ambas llegaron al veredicto y mostraron precio, RSI, rango y volumen vivos.

Encontré fallas reales que conviene corregir antes de la siguiente entrega. El filtro del debate aceptaba órdenes directas de compra; una ruta de Isla podía construir una petición con un host recibido por cabecera y adjuntarle un secreto de Vercel; la síntesis de voz podía quedarse esperando hasta agotar el tiempo del servidor. En iOS había casos de datos malformados y cambios de cuenta que podían causar un cierre inesperado o mostrar datos de la cuenta anterior. El gesto de tocar frente a mantener presionada la píldora también era sensible al tiempo, y el onboarding exponía controles visualmente ocultos a VoiceOver. Las correcciones autorizadas viven solo en la rama local de auditoría, con regresiones específicas.

El principal límite de la auditoría es la medición: hoy no existe un embudo anónimo ni latencias agregadas para saber cuántos usuarios llegan del primer inicio al veredicto, al guardado y al registro, o si el p95 del debate cabe holgadamente en los 100 segundos de iOS. También confirmé que en el proyecto de Vercel de producción no figuran las cuatro variables `APPLE_SIGN_IN_*` que habilitan la revocación automática de Apple durante el borrado de cuenta; el borrado sigue la ruta manual que ya implementa la app. Los cambios de esta auditoría requieren un nuevo build y una decisión tuya antes de enviarlo a Apple.

## Verified findings and disposition

Severity uses **blocker** for a reproducible release-stopping failure, **high** for a material security, crash, quota, or core-loop fault, and **medium** for a bounded degradation. Reproduction below used local fixtures, stubs, source inspection, or screenshots; no real desk calls were used to establish a finding.

### Backend

| Severity | Evidence and reproduction | Disposition |
|---|---|---|
| **High** | `api/_lib/desk-debate.ts:99-132,190-213`: `reviewDeskOutput` accepted `Buy BTC.`, `Buy some BTC right now.`, `Consider buying Bitcoin now.`, `You should purchase BTC today.`, and `Compra un poco de BTC hoy.`. The three agent texts reach the client after this guard. | **Fixed for these reproduced cases in the audit branch.** Added direct and softened advice patterns in English and Spanish, with negation, rejected quotation, and market-description counterexamples. `scripts/test-desk-debate.mts` passes 148 checks. A pattern guard cannot prove that all paraphrases are caught; retain fail-closed output handling and add structured or classifier validation before broader scale. |
| **High, conditional exploitability** | `api/trader-land-share.ts:55-67,96-99`: the handler formed an origin from `x-forwarded-host`/`host`, then sent a fetch to it with `VERCEL_AUTOMATION_BYPASS_SECRET`. A local handler test with an attacker-controlled host and dummy secret produced a request to that host carrying the dummy secret. External exploitability depends on Vercel's header normalization, which was not probed in production. | **Fixed in audit branch.** The route uses the configured site origin or a validated Vercel preview origin, ignores request-supplied host headers, attaches the bypass secret only to that preview, and refuses redirects. `test-trader-land-share.mts` passes 70 checks. |
| **High** | `api/_lib/tts.ts:198-205,234-241,282-293` and `api/_lib/rate-limit-persistent.ts:56,64`: a stubbed provider or rate-limit fetch that never resolves left `bobby-voice-free` pending until its 30-second function limit. The provider fallback could not run. | **Fixed in audit branch.** Persistent limit operations have a 900 ms deadline; voice synthesis has a five-second cap, provider deadlines, and an Edge fallback. Hung-provider and rate-limit tests pass. The Edge WebSocket implementation itself is not cancellable, so a stuck socket may live until the function exits. |
| Medium | `api/desk-debate.ts:17,67-77` derives caller quota from IP and network keys. A phone and Mac on the same hotspot share the 30/day caller key, although the product describes a per-caller allowance. | Propose an installation-scoped, signed, privacy-safe caller token while retaining network and global ceilings. The quota RPC is atomic and fail-closed; preserve that property. |
| Medium | `api/bobby-asset-search.ts:24-41` accepts a public question without a length cap or rate limit; `src/lib/okx-asset-search.ts:783-803` scores each word against the catalogue. A local 1,000-word/50-instrument run took 269 ms, and remote catalogue fetches lack a deadline. | Add a 1,200-code-point input cap, a persistent public limiter, and a source deadline in a later backend batch. Native already caps Núcleo questions, but the public route is independently callable. |
| Medium | `api/stock-candles.ts:37-39`, `api/okx-candles.ts:35-37`: public market endpoints have no explicit upstream deadline or persistent rate limit. `api/progress.ts:109-124` and `api/trader-land.ts:150-155` authenticate reads but do not rate-limit them. | Bound upstream time and review endpoint-specific cost/abuse limits. Keep stale-market refusal rather than displaying old prices as current. |
| Medium | `api/account.ts:122-143` unlinks trades and deletes the Bobby identity before deleting the Supabase Auth user. If the final Auth request fails, deletion is partial until the caller retries; the endpoint does not provide an atomic guarantee across the two services. | Make the deletion workflow resumable and idempotent, and cover a failed final Auth deletion followed by a retry in a local regression. Do not describe a 503 as proof that nothing was deleted. |

`api/desk-debate.ts:64-79` correctly refuses a call if quota storage fails, and the backend verdict schema is `wait|review`. The separate legacy realtime tool schema contains trade-oriented verbs, but Núcleo does not call those tools; it uses only `get_market` and `run_debate` from `voice-tool` for market/pulse data. Desk-owned conviction does not exist yet; Núcleo correctly hides the numeric ring unless the independent pulse agrees with the desk.

Keeping the path for this audit avoids changing the approved glass rendering immediately before a new release, while the Release UI still shows the companion only as an external avatar. ### App Store 1.5 readiness

- **Screenshots:** six PNGs in `docs/app-store/build-40/screenshots/en-US/` are 1320×2868 without alpha, within Apple's [6.9-inch screenshot specification](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications). Their visible UI matches the avatar-outside-glass decision.
- **Speech privacy:** `NucleoSpeech.swift:84-97` requires an on-device-capable recognizer and sets `requiresOnDeviceRecognition`. Apple's [privacy definition](https://developer.apple.com/app-store/app-privacy-details/) treats data as collected when sent off-device and retained beyond servicing a request; the current no-Audio-Data rationale is consistent with local recognition. The resulting question text and narrated reply text still fall under the declared user-content categories. Confirm the saved App Store Connect answers before submission; the repo file alone is not evidence of the online questionnaire.
- **Permission strings:** English and Spanish `NSMicrophoneUsageDescription` and `NSSpeechRecognitionUsageDescription` exist in `project.yml`, `Info.plist`, and `InfoPlist.strings` and explain the feature.
- **Review:** build 40 does not expose swaps or wallet operations through Núcleo; the review notes explain the educational Wait/Review flow. Apple [3.1.5 and 4.3](https://developer.apple.com/app-store/review/guidelines/) remain reviewer decisions. Apple's 2.3.1 requires hidden functionality to be disclosed; the classic exit is DEBUG-only. The account sheet exposes deletion; [Apple's deletion guidance](https://developer.apple.com/support/offering-account-deletion-in-your-app) requires account and associated data removal.
- **Apple revocation configuration:** `vercel env ls production` for project `bobby-agent-trader` listed none of `APPLE_SIGN_IN_TEAM_ID`, `APPLE_SIGN_IN_KEY_ID`, `APPLE_SIGN_IN_CLIENT_ID`, `APPLE_SIGN_IN_PRIVATE_KEY`. `api/account.ts:82-96` therefore selects the existing manual Apple revocation path while still deleting Bobby's account/data. Configure the four values securely if automatic revocation is desired; do not place their values in the repo or this report.
- **Build state:** `project.yml:114-115` is 1.5 (40). The uploaded build 40 cannot gain audit fixes; a later archive needs a new build number. Apple's [manual-release option](https://developer.apple.com/help/app-store-connect/manage-your-apps-availability/select-an-app-store-version-release-option) holds an approved version at Pending Developer Release until Anthony releases it.

## Decisions for Anthony

1. **Next submission:** recommend a new build after audit fixes and complete local gates, rather than submitting the already-uploaded build 40. No audit change has been uploaded.
2. **Fonts:** recommend authorizing a one-time download and bundling of the licensed font files, with a before/after offline visual check.
3. **Apple revocation:** recommend configuring the four `APPLE_SIGN_IN_*` values through Vercel's secret settings so deletion can revoke Apple access automatically; the manual in-app path currently remains available.
4. **Product measurement:** recommend an opt-in-free, content-free anonymous funnel using randomized installation IDs already disclosed as Device ID, event names only, coarse duration buckets, and short retention. Decide retention and whether to add a diagnostics category before enabling it.
5. **Next-level order:** recommend web parity, then the Record face with explicit simulated-data labeling, then Android and notifications. Streaming and authored speech should follow latency/guard measurements.
